# Proposal

## Why

Пользователь может открыть issue и прочитать описание, но пока не может вести обсуждение на его странице. Первая часть лабораторной №5 добавляет жизненный цикл комментария с историей и модерацией, на который могут опираться следующие части работы.

## What Changes

- Показать на странице issue список комментариев с пагинацией, автором, датой создания и отметкой о последнем редактировании. Публикация и правка используют существующий MarkdownEditor и предпросмотр.
- Добавить Server Actions для публикации, редактирования, мягкого удаления, восстановления, скрытия и раскрытия. Хранить историю правок в `comment_revisions`, а изменения видимости фиксировать в журнале действий.
- Проверять доступ к issue и комментариям на сервере. Разрешать владельцу репозитория скрывать комментарий с причиной из `hidden_reason`. Использовать одну безопасную политику Markdown при чтении, предпросмотре и просмотре истории.
- Сразу показывать публикацию и правку как ожидающие сохранения. При ошибке восстанавливать подтверждённое состояние и сохранять черновик.
- Покрыть изменения unit-, integration- и E2E-тестами. Сохранить поиск по видимым комментариям и сортировку issues по их количеству.
- Упоминания, реакции, подписки и уведомления относятся к следующим частям лабораторной.

## Capabilities

### New Capabilities

- `issue-comments` — чтение, публикация и правка комментариев, история, восстановление, модерация и безопасное отображение.

### Modified Capabilities

## Impact

- Страница `/[user]/[repository]/issues/[number]`, запросы issues, новые модели и Server Actions комментариев, существующие компоненты Markdown и UI.
- Существующие таблицы `comments`, `comment_revisions` и `issue_events`. При реализации понадобятся версионированные изменения схемы, совместимые с импортированными данными.
- Поиск, счётчики и сортировка issues, повторный импорт, ключи кэша и существующий тестовый контур Vitest, Playwright, PostgreSQL и Webdis.
